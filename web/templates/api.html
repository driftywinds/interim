Tools to interact with interim programmatically. The API is versioned, JSON-first, and available at {{.APIBase}}.

All files are automatically and permanently deleted after {{.RetentionLabel}}. Storage is capped at {{.MaxStorage}}; uploads are rejected with HTTP 507 when full.

Overview Authentication Quickstart Endpoints Errors OpenAPI JSON YAML

Overview

Base URL: {{.APIBase}}

Uploads are multipart/form-data requests. Anonymous uploads are allowed. A user hash identifies an API client and lets it list and delete its own files. Every response is JSON, except DELETE, which returns 204 No Content.

Retention: {{.RetentionLabel}} per file, configured by this instance's operator. Per-file limit: {{.MaxFileSize}}. Signed URL lifetime: {{.DownloadTTL}}.

Authentication

Create a user hash with POST /keys. It is returned once. Send it on every authenticated request:

Authorization: Bearer interim_...

X-API-Key: interim_... is also accepted. Anonymous upload and public metadata/download endpoints do not require a hash. An invalid supplied hash is always rejected.

Lost hashes cannot be recovered. Only a SHA-256 hash is stored on the server.

Quickstart

1. Create a user hash

curl -X POST {{.BaseURL}}/api/v1/keys \
  -H 'Content-Type: application/json' \
  -d '{"name":"my-cli"}'

2. Upload a file

curl -X POST {{.BaseURL}}/api/v1/files \
  -H 'Authorization: Bearer interim_...' \
  -H 'X-File-Size: 12345' \
  -F 'file=@sample.bin'

The response includes id, page_url, expires_at, and a one-time delete_token. Keep the delete token if you uploaded anonymously.

3. Ask for a signed download link

curl -X POST {{.BaseURL}}/api/v1/files/FILE_ID/download

The returned url is a short-lived signed S3 URL. Do not store it; request a new one when needed.

4. Delete a file

curl -X DELETE {{.BaseURL}}/api/v1/files/FILE_ID \
  -H 'Authorization: Bearer interim_...'

Anonymous uploads are deleted with the per-file token:

curl -X DELETE {{.BaseURL}}/api/v1/files/FILE_ID \
  -H 'X-Delete-Token: THE_TOKEN_FROM_UPLOAD'

Endpoints

Create a user hash POST /keys

Creates an API credential. No authentication required. Subject to per-IP rate limits.

POST {{.APIBase}}/keys
Content-Type: application/json

{"name":"optional label"}
HTTP/1.1 201 Created
{
  "id": "…",
  "user_hash": "interim_…",
  "key_prefix": "interim_…",
  "created_at": "2026-10-25T09:00:00Z",
  "warning": "Save this user hash now. It is shown once and cannot be recovered."
}
Get current user hash GET /keys/me

Requires a bearer user hash. Returns the key prefix and usage counts.

GET {{.APIBase}}/keys/me
Authorization: Bearer interim_...
Upload a file POST /files

Multipart field name: file. Authentication is optional. Send X-File-Size with the exact byte size; without it, a Content-Length request body is required.

POST {{.APIBase}}/files
Authorization: Bearer interim_...      # optional
X-File-Size: 12345                     # recommended
Content-Type: multipart/form-data

file=@sample.bin

Possible errors: 413 file_too_large, 507 storage_full, 502 storage_error.

List your files GET /files

Requires a bearer user hash. Returns only that hash's active files. Query: limit (1–100) and offset.

GET {{.APIBase}}/files?limit=50&offset=0
Authorization: Bearer interim_...
Get file metadata GET /files/{id}

Public. Includes the page URL, size, content type, creation time, and expiry. It never exposes the object key or delete token.

GET {{.APIBase}}/files/FILE_ID
Create a signed download link POST /files/{id}/download

Public. Returns a private S3 URL signed for {{.DownloadTTL}}.

POST {{.APIBase}}/files/FILE_ID/download
{
  "url": "https://storage.example/...signature...",
  "filename": "sample.bin",
  "expires_at": "2026-10-25T09:05:00Z"
}

Expired files return 410 Gone. Do not cache or redistribute signed URLs.

Delete a file DELETE /files/{id}

Requires either the owning user hash or the per-file delete token. Returns 204 on success.

DELETE {{.APIBase}}/files/FILE_ID
Authorization: Bearer interim_...
# or
X-Delete-Token: token_from_upload
Storage status GET /status

Public. Reports whether uploads are currently accepted, used/reserved bytes, the configured cap, retention, and per-file limit.

GET {{.APIBase}}/status

Errors and limits

StatusCodeMeaning
400invalid_requestMalformed JSON, form, or upload.
401unauthorizedMissing or invalid user hash.
403forbiddenInvalid per-file delete token.
404not_foundUnknown file or endpoint.
410expiredThe configured retention period has ended.
413file_too_largeExceeds the per-file cap.
429rate_limitedToo many requests; check Retry-After.
507storage_fullNo storage capacity available.

Errors use a single envelope:

{
  "error": {
    "code": "storage_full",
    "message": "Storage maxed out — please try again later.",
    "request_id": "…"
  }
}

Send X-Request-ID in bug reports; the server also returns one on every response. API responses are Cache-Control: no-store.
